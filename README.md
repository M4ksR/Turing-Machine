# Интерпретатор Машин Тьюринга

Машина Тьюринга (МТ) — абстрактная вычислительная машина, понятие введенное английским математиком Аланом Тьюрингом в 1936 году как формализация понятия алгоритма.
Любая функция, которая может быть вычислена физическим устройством, может быть вычислена машиной Тьюринга, что приводит к тому, что все выводы касающиеся абстрактной машины Тьюринга, полностью применимы к любым компьютерам на любой архитектуре.

В нашем случае рассматривается модификация МТ, заданая следующим образом:

1. лента, замкнутая в кольцо (фиксированное количество ячеек);
2. алфавит `{'0', '1'}`;
3. множество состояний `Q = {q_i, i=1...N}`;
4. программа (набор правил) вида `q_i a_j -> q_k a_m d_n`, где 
* `q_i` — состояние, в котором находится машина (слово длиной не более 15 символов), 
* `a_j` — символ из алфавита, записанный в обозреваемой ячейке,
* `q_k` — состояние, в которое переходит машина (слово длиной не более 15 символов),
* `a_m` — символ из алфавита, записывается в ячейку вместо `a_j`,
* `d_n` — движение головки, которое имеет три варианта: на ячейку влево (L), на ячейку вправо (R), остаться на месте (N);
5. начальное состояние — первое состояние, записанное в программе.

Состояние, для которого не определено правило, является заключительным. Попав в него, машина останавливается.

Программа МТ записана в файле, имя которого будет передаваться в программу в командной строке.
Файл содержит строки в формате `q_i a_j -> q_k a_m d_n`, например, файл `MT.txt`:
```
q1 0 -> q2 1 R
q1 1 -> q2 1 L
q2 0 -> q1 1 L
q2 1 -> q3 1 L
```

## Busy beaver

Одной из проблем в теории алгоритмов является проблема остановки (Halting problem), которая может неформально быть поставлена в виде: для данного описания процедуры и её начальных входных данных определить, завершится ли когда-либо выполнение процедуры с этими данными; либо, что процедура всё время будет работать без остановки.
Алан Тьюринг доказал в 1936 году, что проблема остановки неразрешима на машине Тьюринга. Другими словами, не существует общего алгоритма решения этой проблемы.
На практике это означает, что компьютер сам никогда не сможет определить точно, зависнет ли его очередная программа в бесконечном потоке инструкций или нет.

Если ограничить машину Тьюринга (MT) `N` состояниями, то можно создать конечное число машин.
При росте количества состояний `N`, количество возможных машин Тьюринга растет быстрее чем экспоненциально: (4(n+1))<sup>2n</sup>.
Среди МТ будут два типа машин — те, что останавливаются и нет.

В 1962 году венгерский математик Tiber Rado в статье "On non-computable functions"[^1] задался следующими вопросами:
* Какое максимальное количество операций может совершить МТ с `N` состояниями до своего завершения? Это называют числом **Busy Beaver**, обозначается как `BB(n)` или `S(n)`.
* Какое максимально количество единиц может напечатать МТ с `N` состояниями на пустой ленте до завершения? Обозначается как `Σ(n)`.

Ответить на эти вопросы оказалось совсем не просто. Функция Busy beaver невычислима.

На текущий момент известны точно только следующие значения[^2]:
|       | N=2 | N=3 | N=4 |    N=5   |
| ----- | --- | --- | --- | -------- |
| BB(N) |  6  | 21  | 107 | 47176870 |
| Σ(n)  |  4  |  6  |  13 |   4098   |

Для того, чтобы пытаться вычислять значение функции BB(N) или Σ(n) и нужен интерпретатор машин Тьюринга.

## Возможности интерпретатора

1. Вычисление для заданной программы МТ количества тактов до остановки машины и вывода того, что будет на ленте.

Интерпретатор вызывается с тремя аргументами командной строки:
1. имя файла с программой МТ,
2. размер ленты,
3. максимальное количество тактов работы машины.

Например, вызов `tm MT.txt 1000 1000000` должен запустить программу записанную в файле `MT.txt` на пустой ленте длиной 1000 ячеек, замкнутой в кольцо и выполнить не более 1'000'000 тактов работы машины.

Если в ходе работы МТ не остановилась за максимально разрешенное количество тактов работы, то остановить машину и вывести сообщение `Not applicable`.
В остальных случаях вывести в первой строке количество тактов до остановки, а во второй строке содержимое ленты, начиная с позиции, на которой остановилась МТ, и до последней 1 на ленте (учесть, что лента замкнута в кольцо).
Если в результате работы на ленте не было ни одной 1, то вывести `0`.

Например, после вызова интерпретатора `tm MT.txt 1000 1000000` в результате работы должны получить:
```
6
1111
```

2. Выполнение программы с заданными входными данными.

Интерпретатор вызывается с четырмя аргументами командной строки:
1. имя файла с программой МТ,
2. размер ленты,
3. максимальное количество тактов работы машины,
4. имя файла с входной информацией на ленте.

Входная информация на ленте помещается, начиная с нулевой ячейки.

Например, если файл `input.txt` содержит:
```
1101011111
```
то команда `tm MT.txt 1000 2000000 input.txt` выполняет программу из файла `MT.txt` на ленте, замкнутой в кольцо, на которой 1000 ячеек и исходно содержится `1101011111`, а остальные элементы `0`. Максимальное количество тактов работы машины 2000000.

Если в ходе работы МТ не остановилась за максимально разрешенное количество тактов работы, то остановить машину и вывести сообщение `Not applicable`.
В остальных случаях вывести содержимое ленты, начиная с позиции, на которой остановилась МТ, и до последней 1 на ленте.
Если в результате работы на ленте не было ни одной 1, то вывести `0`.

## Требования к реализации

Реализовать как минимум следующие классы:
* `State` — класс для определения состояния МТ,
* `Command` — класс для определения одной команды программы МТ,
* `Programm` — класс для определения программы МТ,
* `Tape` — класс для задания ленты, на которой производятся вычисления,
* `TuringMachine` — класс для МТ.

Для класса `TuringMachine`:
* Заголовочный файл — `turingmachine.h`
* Файл реализации — `turingmachine.cpp`

Для класса `Programm` реализовать:
* конструктор для задания программы МТ (аргумент: название файла с программой);
* метод `Command get(const State& q_i, char a_j) const`, возвращающий команду для заданной комбинации состояния и символа.

Если программа (какая-то строка программы) содержит ошибку, то необходимо вывести сообщение `Error: invalid programm` и прекратить работу программы.

Для класса `Tape` реализовать:
* конструктор `Tape(size_t maxsize, const char str[])` с двумя аргументами — размер ленты и строка с исходными данными;
* `operator []`, позволяющий получить доступ к содержимому по номеру ячейки на ленте.

Если исходных данных больше, чем размер ленты вывести сообщение `Error: invalid tape maxsize`.

Если во входной строке содержатся символы не из алфавита, то вывести сообщение `Error: invalid input data`.

Для класса `TuringMachine` реализовать:
* конструктор для задания машины (аргумент: программа);
* метод `unsigned long long calc(Tape & tape, unsigned long long maxsteps)`, выполняющий программу, на ленте tape с заданным исходным состоянием, максимальным количеством тактов работы машины, заданным в maxsteps, и возращающий количество выполненных тактов (если ответ более maxsteps, то машина не остановилась за заданное количество тактов).

Ограничений на дополнительные методы в классах и на дополнительные классы нет.Упомянутые конструкторы и методы классов являются обязательными для реализации, но допустимы любые другие требуемые для реализации задачи.

Требования:
* При разработке классов учитывать принципы идиомы RAII (Resource Acquisition Is Initialization).
* Программа не должна использовать контейнеры STL (std::vector и т. д), исключение `std::string`.

[^1]: [Tiber Rado. On non-computable functions](https://gwern.net/doc/cs/computable/1962-rado.pdf)
[^2]: [Busy beaver](https://en.wikipedia.org/wiki/Busy_beaver)
